## Still open / intentional limits

### High (physics / honesty, not a crash)

- **2 boards ≠ room map.** Path TX/mid/RX is a soft fade estimate; desks off the beam stay quiet.
- **Fade→RX bias** can mis-label “near TX” if the body shadows the link the same way. Hysteresis reduces thrash; it does not create real localization.
- **Live amp_std often very high** on school Wi‑Fi (~10–15). Empty calibrate with someone on the path poisons baseline → constant “presence.” Always calibrate empty.

### Medium

- **Firmware `sc[]` is synthetic** (RSSI history + sine). Waterfall looks “CSI-like” but is not PHY CSI — UI/docs must stay honest.
- **RuView orange Demo button** still invents stick figures (upstream UI). Our pose stream does not invent limbs from radio alone.
- **School Wi‑Fi client isolation** — PC→board UDP commands often fail; serial fallback exists. LED mode switches may need USB.
- **Windows single-instance lock** uses `OpenProcess`; rare false negatives under permission weirdness could allow a second host bind fight.
- **Default firmware Wi‑Fi password** in source (`change-me-lab-only`) for hotspot demos — change for anything non-lab.
- **BLE phone positions** in 3D are a hash of MAC → angle, not localization (decorative).

### Low / cleanup

- Camera/face routes still in FastAPI (`/api/camera.*`, enroll) while LEX UI is radio-only — fine for optional `--camera`, slightly confusing.
- `docs/` / README still say “CSI” in many places; report clarifies RSSI.
- No automated pytest suite (`test_*.py` absent).
- `tools/_audit_dsp.py` was a one-off probe (safe to delete).
